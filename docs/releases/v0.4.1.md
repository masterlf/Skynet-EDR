# Skynet-EDR v0.4.1 — continuous passive P1 coverage

Skynet-EDR v0.4.1 is an installable **prerelease** for evaluation and lab deployment. It remains passive and read-only: it detects and records but does not block agent actions.

## Highlights

- Added authenticated AF_UNIX continuous ingestion with exact bounded event projection, pseudonymized correlation identities, durable checkpoints, and collision-safe acknowledgements.
- Added transactionally bounded continuous `EDR-EXFIL-001` and `EDR-MALWARE-001` detection, including trigger-anchored linear two-step evaluation and deterministic duplicate-rule rejection.
- Added token-bounded harmless malware-test classification so exact canaries classify while prefix/suffix near-markers fail dark.
- Added privacy-safe Hermes parameter/result classification without persisting raw tool inputs, outputs, prompts, commands, schedules, or job identifiers.
- Added `agent.automation.scheduled` only for proven completed built-in Hermes `cronjob` create/update outcomes with strict bounded result validation.
- Added release-tag/package-version consistency validation so a tag cannot silently publish mismatched package or plugin versions.
- Exercised clean-container Ubuntu DEB and tarball install/remove/purge paths without service start. This does not establish daemon-runtime, producer-enrollment, upgrade, or rollback support outside the documented evaluation scope.

## Install quickly

Download a package within the [MVP public support contract](../MVP_SUPPORT_MATRIX.md) together with `checksums.txt`, then verify it:

```bash
sha256sum -c checksums.txt --ignore-missing
```

Debian/Ubuntu/Mint:

```bash
sudo apt install ./skynet-edr_0.4.1_amd64.deb
skynet-edr --version
skynet-edr-daemon status
skynet-edr doctor
```

RHEL/Fedora-compatible:

```bash
sudo dnf install ./skynet-edr-0.4.1-1.x86_64.rpm
```

Arch:

```bash
sudo pacman -U ./skynet-edr-0.4.1-1-x86_64.pkg.tar.zst
```

Tarball:

```bash
tar -xzf skynet-edr-0.4.1-x86_64-unknown-linux-gnu.tar.gz
cd skynet-edr-0.4.1-x86_64-unknown-linux-gnu
sha256sum -c SHA256SUMS
sudo ./install.sh
```

## Upgrade and rollback

Preserve `/etc/skynet-edr/` and `/var/lib/skynet-edr/` before an upgrade. For a Debian/Ubuntu rollback procedure, stop the service, install a previously verified DEB, restore state only if a migration requires it, and start the service again. These are operator procedures, not v0.4.1 runtime validation evidence: the release checks did not exercise package upgrade or rollback, service start/restart persistence, or service/API health.

## Security boundary and limitations

- Config, generic persistence, and approval/scope mutation telemetry remains deliberately dark because current Hermes lifecycle evidence does not prove the persisted post-mutation outcome.
- Cron coverage is narrow: only exact built-in `cronjob` create/update results proving an enabled active scheduled job emit the mutation event. Intent, malformed or ambiguous JSON, duplicate keys, blocked/error results, inactive jobs, and near-allowlist names fail dark.
- AF_UNIX UID authorization and reported runtime roles authorize a producer; they do not attest the process or make producer-supplied facts inherently trustworthy.
- No inline blocking, guard/enforcement mode, privileged kernel/eBPF sensor, signed packages, SBOM, or provenance attestation yet.
- Windows and macOS runtime packages are not included in this prerelease.
