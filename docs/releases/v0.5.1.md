# Skynet-EDR v0.5.1 — deployment integrity hotfix

Skynet-EDR v0.5.1 is a passive Linux-first prerelease. It does not add blocking or containment. This hotfix is release-blocking because it closes the DEB/systemd test gap that allowed privileged package inspection to leave persistent directories inaccessible to the real service identity.

## What changed

- Package inspection is listing/query based. Root package extraction on a live or persistent host is explicitly prohibited.
- The package-owned `/usr/libexec/skynet-edr/deploy-verify` checks exact object-type/owner/group/mode tuples, `skynet-edr` DAC access, the real systemd process UID, installed executable identity, and bounded loopback-only status/risks/rules read-only HTTP contracts. It is read-only and has no repair mode.
- PR and release package workflows are configured to run the real DEB/systemd unit only after GitHub-hosted/disposable-runner interlocks pass. The configured gate is intended to prove that the installed verifier matches the reviewed source and package integrity, that state is writable as `skynet-edr`, and that the installed verifier fails after injected `root:root` state drift. Exact-final-tree hosted execution evidence remains pending until those jobs are green and retained.
- `docs/DEPLOYMENT.md` defines the package-manager-only deployment and rollback procedure.

## Install

Verify `checksums.txt`, then use APT only:

```sh
sudo apt-get install --no-install-recommends ./skynet-edr_0.5.1_amd64.deb
```

Do not use `dpkg -i`, package extraction, copied binaries, force flags, or tar deployment on a persistent host. Service restart remains a separate operator approval.

## Rollback

Stop the service, install a previously checksum-verified DEB with APT, start the service, and run the verifier against the previous version. Preserve the current database and configuration. Database restoration and ownership repair are separate incident actions, never automated rollback steps.

## Security impact

This release prevents a recurrence class by separating safe artifact inspection from live deployment and by promoting service-identity/path-access evidence into the release gate. It does not claim that package-manager installation can defend against arbitrary privileged host mutation after deployment.

## Residual limitations

The authoritative vertical gate is bounded to Ubuntu/Debian `amd64`, DEB, and systemd. RPM, Arch, non-systemd systems, database downgrade compatibility, production auto-repair, and live Hermes reload/enrollment remain unqualified or explicitly blocked. Skynet-EDR remains an evaluation prerelease without production support commitment.
