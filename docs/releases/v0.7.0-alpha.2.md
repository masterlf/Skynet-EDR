# Skynet-EDR v0.7.0-alpha.2 — real Hermes detection journey

Skynet-EDR v0.7.0-alpha.2 is a passive Linux-first prerelease candidate for one exact evaluation cell: Ubuntu 24.04 amd64/systemd, the native DEB, Hermes Agent 0.20.0, and the `default` profile. It adds one safe real-dispatch journey for the existing `EDR-MALWARE-001` rule. It does not add detection rules, prevention, containment, outbound delivery, retention, backup, signing, SBOM, provenance, or broader platform/runtime support.

## Exact scope and identity

- Canonical product, Rust crates, Hermes plugin/payload, dashboard, browser gate, package workflow, and current documentation use `0.7.0-alpha.2`.
- DEB and RPM native package identity is `0.7.0~alpha.2`; Arch identity is `0.7.0.alpha.2-1`.
- Hermes compatibility remains exact version 0.20.0 and the `default` profile.
- The other six existing detection paths retain their previous narrow evidence level; one real journey is not evidence that every rule or producer shape works end to end.

## Safe simulation contract

The Hermes plugin registers `skynet_edr_safe_detection_simulation` in the `skynet_edr` toolset. It accepts exactly `{"scenario":"malware-marker"}`. Missing, unknown, or additional input fails closed. Its handler reads no arbitrary file, starts no process, and opens no external network connection. It emits one fixed canonical event through the existing bounded local telemetry transport and returns only a fixed redacted status. It reports `submitted` only after an authenticated accepting ACK or a confirmed durable fallback write; disabled telemetry, collision, permanent rejection, and a full or inaccessible fallback report `not_submitted`.

On the default Hermes 0.20 deferred-tool path, the deterministic release gate drives `tool_search → tool_describe → tool_call`. The real registry dispatch invokes the plugin handler; the handler produces one redacted canonical event and suppresses a duplicate if the runtime also invokes `post_tool_call`; authenticated protocol-v3 AF_UNIX ingestion commits the event; the existing correlator opens exactly one high-severity `EDR-MALWARE-001` incident; the loopback API and authenticated Risk Explorer render the deterministic redacted projection.

The package-owned synthetic secret exists only in controlled test input. It must not appear in the plugin handler result, canonical producer output, fallback output, SQLite events/incidents, local notices, diagnostics, loopback API responses, or rendered browser text. Release acceptance scans those surfaces explicitly.

## Claim boundary

The release remains passive. It detects and stores redacted local evidence and exposes local read-only investigation surfaces; it does not block, approve, pause, quarantine, contain, or change agent actions. The safe simulation proves only the allowlisted `EDR-MALWARE-001` marker shape. A negative result is not a safety verdict.

RPM, Arch, and tarball runtime behavior; non-Ubuntu systems; non-systemd systems; other architectures; custom Hermes homes/profiles; Hermes versions other than 0.20.0; and other AI runtimes remain unsupported or unqualified.

## Promotion gates

Passing unit tests or directly invoking plugin callbacks is insufficient. Promotion requires the exact candidate package to pass:

1. reproducible package builds from the primary and detached clean worktrees;
2. CI artifact equality and fail-closed expected-SHA checks;
3. disposable Ubuntu 24.04 clean-host package/systemd and complete Hermes enrollment/unenrollment acceptance;
4. the real deferred-tool dispatcher journey through authenticated ingestion, SQLite correlation, loopback API, and browser Risk Explorer;
5. bounded secret-marker scans over producer output, SQLite, notices, diagnostics, API, and rendered browser text;
6. all seven existing synthetic regression scenarios and hostile/benign controls;
7. a sealed private evidence bundle and exact-commit/exact-artifact security review with no remaining critical or high blocker.

The accepted source commit, final DEB SHA-256, clean-host verdict, reviewer verdict, and public tag are recorded only after those gates complete. Any production-byte change after acceptance requires a rebuild, a new SHA, a new clean-host pass, a new sealed evidence bundle, and a new security verdict.
