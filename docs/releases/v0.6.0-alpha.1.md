# Skynet-EDR v0.6.0-alpha.1 — local incident notifications

Skynet-EDR v0.6.0-alpha.1 is a passive Linux-first evaluation prerelease. It adds a local operator notification path; it does not add blocking, containment, outbound delivery, or delivery replay.

## What changed

- After a continuous-ingestion transaction commits a newly opened incident, the daemon writes one compact `skynet.alert.notice.v1` JSON line to stdout for systemd/journald capture.
- Notices contain only the bounded safe incident identifier, lowercase severity, bounded server-redacted summary, and incident creation timestamp. Event payloads, source identities, paths, tool arguments, and raw content are excluded.
- Duplicate event replay emits no second notice.
- A stdout/sink failure does not roll back the committed event, incident, or receipt and does not revoke the producer ACK. It increments `alert_delivery_errors_total`, records the fixed `alert_delivery` source error category, and temporarily degrades ingestion health.
- Release-version validation now accepts canonical SemVer prereleases such as `0.6.0-alpha.1` while rejecting leading-zero, empty-identifier, and build-metadata forms used outside this release contract.
- Artifact filenames retain `0.6.0-alpha.1`; verified native metadata uses `0.6.0~alpha.1` for DEB/RPM and `0.6.0.alpha.1-1` for Arch so every ecosystem preserves prerelease identity and ordering instead of silently publishing `0.6.0`.

## Operations

When the daemon runs under systemd, inspect notices with:

```sh
journalctl -u skynet-edr.service -o cat | grep '"schema_version":"skynet.alert.notice.v1"'
```

The stdout line is a best-effort local notification, not a durable outbox. SQLite remains authoritative. If `alert_delivery_errors_total` increases, query the local read-only API/CLI for committed incidents and investigate stdout/journald availability.

## Install

Verify `checksums.txt`, then use the package-manager-only procedure in [Install](../INSTALL.md). Service restart remains a separate operator approval.

## Security impact

The notification is derived only from the incident object after server-side storage redaction. Delivery has no network egress and no new dependency or process. Sink failure is visible but cannot make an already committed event retry, preventing duplicate producer replay from being used as an alert amplifier.

## Residual limitations

Notifications are stdout-only and best effort: there is no alert JSONL file, rotation, outbox, replay, webhook, email, SIEM transport, or delivery acknowledgement. Process-lifetime counters reset on daemon restart. Skynet-EDR remains passive and not production-supported.
