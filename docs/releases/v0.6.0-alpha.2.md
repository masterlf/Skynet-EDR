# Skynet-EDR v0.6.0-alpha.2 — status contract compatibility

Skynet-EDR v0.6.0-alpha.2 is a passive Linux-first evaluation prerelease. It repairs the producer/dashboard status contract regression introduced by v0.6.0-alpha.1; it does not add blocking, containment, outbound delivery, or delivery replay.

## What changed

- The Rust ingestion producer now owns one typed, bounded source-error category contract with fixed serialized names and degradation semantics.
- The contract includes the v0.6.0-alpha.1 `alert_delivery` category emitted when a post-commit local incident notice cannot be written.
- The dashboard derives accepted categories and recent-error degradation behavior from the producer-owned contract fixture. Unknown, altered, duplicate, or self-declared categories fail closed.
- An HTTP 200 status response with an incompatible contract is shown as contract-incompatible, not as transport offline.
- Recent `alert_delivery` failures keep the engine and read-only backend available while telemetry is visibly degraded.

## Incident and deployment status

v0.6.0-alpha.1 emitted `alert_delivery`, but its dashboard validator omitted that value and falsely rendered the engine/backend offline after receiving an otherwise valid HTTP 200 status document. v0.6.0-alpha.2 corrects that contract mismatch.

This PR does not establish deployability. v0.6.0-alpha.2 remains gated by follow-up PR B and a separately approved live deployment. No host mutation, service restart, tag, release publication, or deployment is performed by this change.

## Security impact

The dashboard continues to reject arbitrary categories and contradictory health objects. Contract incompatibility remains fail-closed without reflecting hostile values, while transport failure and valid degraded telemetry remain visibly distinct.

## Residual limitations

Skynet-EDR remains passive and not production-supported. Local incident notices remain stdout-only and best effort. Process-lifetime counters reset on daemon restart. Follow-up PR B and live deployment validation remain required before release promotion.
