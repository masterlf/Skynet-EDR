# Skynet-EDR v0.6.0-beta.1 — threat-validated passive detection

Skynet-EDR v0.6.0-beta.1 is a passive Linux-first evaluation prerelease. It adds a reusable offline Threat Validation Suite and a version-specific public protection matrix. It does not add prevention, guard mode, containment, outbound delivery, retention/purge, signing, SBOM, provenance, or broader producer/platform support.

## Shipped in this tranche

- A strict repository-owned `skynet.threat-validation-manifest.v1` contract consolidates the existing S2 corpus with immutable IDs, malicious/benign/hostile-malformed categories, exact outcomes, engine/producer paths, evidence strength, compatibility, and explicit limitations.
- A dependency-free deterministic runner validates duplicate/unknown/invalid scenarios and matrix drift, executes the bounded Rust engine and shipped Hermes producer fixture gates offline, and writes `skynet.threat-validation-evidence.v1` JSON plus a concise summary.
- The representative suite covers positive and benign near-miss fixtures for all seven currently shipped narrow live rule paths, hostile malformed parser inputs, fake-marker redaction, and explicit skipped producer-dark scenarios.
- The public v0.6.0-beta.1 protection matrix uses only `DETECTED_AND_TESTED`, `PARTIAL`, `NOT_TESTED`, and `NOT_COVERED`, with scenario evidence and limitations.
- Normal CI, S2 validation, and the release-candidate workflow run the bounded suite without adding it to every unit-test invocation.
- Canonical product, plugin, package, browser-gate, and documentation identities advance to `0.6.0-beta.1`; Debian metadata uses `0.6.0~beta.1`.

## Evidence boundary

Passing evidence proves only that the declared synthetic offline fixtures met their exact expectations. Plugin callbacks are invoked directly; actual Hermes discovery/dispatcher ABI is `NOT_TESTED`. External canonical producers are `PARTIAL`. `EDR-CONFIG-001`, `EDR-SCOPE-001`, `EDR-PERSIST-001`, and standalone `EDR-SECRET-001` remain `NOT_COVERED` through the shipped Hermes path.

Skynet-EDR remains passive. A green suite does not prove universal detection, prevention, production performance, package runtime compatibility, or safety of an action that produced no incident.

## Upgrade and rollback

Use the package-manager upgrade and rollback procedures in [Install](../INSTALL.md#upgrade-and-rollback). Back up local state before changing versions. Rollback changes binaries and integration payloads; it does not rewrite or purge existing local evidence.
