## Public artifacts and checksum verification

Download artifacts and `checksums.txt` from the public GitHub release page. Verify downloaded bytes before installation from the directory containing them:

```bash
sha256sum -c checksums.txt --ignore-missing
```

The command must report `OK` for each artifact being used. A missing checksum entry, mismatch, renamed unexpected file, or unavailable public release is a stop condition; do not install unverified bytes. Release publication revalidates `dist/checksums.txt`, uses these reviewed notes, refuses to replace an existing release, and verifies the tag.

No artifact signing, SBOM, or provenance attestation is claimed for v0.6.0.

## Upgrade and rollback

Follow [Install: upgrade and rollback](../INSTALL.md#upgrade-and-rollback). Back up required local state before changing versions. Use the native package manager for both upgrade and rollback; do not manually overwrite package-owned files. After either direction, re-run checksum/package-integrity and deployment verification before restarting service use.

Rollback changes binaries and integration payloads. It does not rewrite, migrate backward, or purge existing local evidence. Database downgrade compatibility and automated restore are not qualified; preserve backups and stop if the previous binary cannot safely read current state.
