# Skynet-EDR v0.7.0-alpha.1 — autonomous Hermes 0.20 enrollment

Skynet-EDR v0.7.0-alpha.1 is a passive Linux-first prerelease for one exact evaluation cell: Ubuntu 24.04 amd64/systemd, the native DEB, Hermes Agent 0.20.0, and the `default` profile. It does not add detection rules, blocking, containment, outbound delivery, retention, backup, signing, SBOM, provenance, or broader platform/runtime support.

## Exact scope and identity

- Canonical product, Rust crates, Hermes plugin/payload, dashboard, browser gate, package workflow, and current documentation use `0.7.0-alpha.1`.
- DEB and RPM native package identity is `0.7.0~alpha.1`; Arch identity is `0.7.0.alpha.1-1`.
- The enrollment transaction rejects Hermes 0.19.0 and every version other than exact 0.20.0.
- Historical v0.6.0 coverage evidence remains authoritative for the seven existing narrow detection paths; this release does not generalize those claims.

## Enrollment contract

The package-owned `skynet-edr-hermes-enroll check|apply|verify|unenroll` transaction preserves dry-run behavior, idempotence, bounded deadlines, exact package/plugin identity, private redacted evidence, non-destructive quarantine, fail-closed drift handling, and explicit rollback authority.

`ENROLLED` requires the exact target account and canonical `<passwd home>/.hermes`, package-owned payload bytes, Hermes 0.20.0/default-profile identity, the documented loopback A2A listener at `127.0.0.1:9900`, explicit authorization for a complete `user@UID.service` stop/start, healthy protocol-v3 gateway producer evidence, fresh process/source binding, a committed harmless attestation receipt, a completed real dispatcher response, and the exact three-event producer advancement. File presence and plugin-enable success are not enrollment proof. The authorized transition interrupts every service managed by that user manager, not only Hermes, but never calls `loginctl terminate-user` and does not authorize unrelated login-session termination.

Unenrollment restores the adapter-recorded pre-enrollment config, unit/drop-in, group-membership, and plugin-enable state, then moves the exact managed generation and transaction metadata into root-owned non-destructive quarantine. Quarantine and recovery evidence require manual operator inspection and are not automatically purged.

The adapter binds disable to exact enabled and expected-disabled Hermes configuration fingerprints. Drift before, during, or after disable fails closed rather than allowing rollback to overwrite a concurrent operator change.

## Claim boundary

The release remains passive. It detects and stores redacted local evidence and exposes local read-only investigation surfaces; it does not block, approve, pause, quarantine, contain, or change agent actions. RPM, Arch, tarball runtime behavior, non-Ubuntu systems, non-systemd systems, other architectures, custom Hermes homes/profiles, Hermes versions other than 0.20.0, and other AI runtimes remain unsupported or unqualified.

Passing deterministic fixtures is insufficient for release promotion. The exact candidate package must pass the disposable Ubuntu 24.04 clean-host package/systemd, browser, threat-validation, and Hermes apply/verify/repeat-apply/unenroll gates with a sealed redacted evidence bundle.

Release publication is additionally pinned in CI to the exact accepted DEB SHA-256 recorded below; a tag rebuild with different bytes fails before upload. Artifacts remain unsigned and this alpha does not provide an SBOM or external provenance attestation.

Follow [Install: upgrade and rollback](../INSTALL.md#upgrade-and-rollback). Preserve local state before changing package versions. Use native package-manager operations; do not overwrite package-owned files manually. Database downgrade compatibility and automated restore remain unqualified.
