# Skynet-EDR v0.6.0-alpha.3 — deployable passive detection

Skynet-EDR v0.6.0-alpha.3 is a passive Linux-first evaluation prerelease. It carries forward the alpha.2 producer/dashboard status contract and corrects the package and deployment gates. It does not add blocking, containment, outbound delivery, replay, webhook, email, SIEM, purge, or S3 scope.

## What changed

- The canonical product identity is exactly `0.6.0-alpha.3`; the native Debian identity is separately and exactly `0.6.0~alpha.3`.
- The preinstall DEB metadata, installed `dpkg` metadata, CLI, daemon, and API versions are bound by exact equality. Epochs, revisions, and near matches fail closed.
- The package ships a root-owned Hermes payload manifest and package-owned verifier. Exact directory and file allowlists, descriptor-relative no-follow traversal, ownership, modes, regular-file type, single-link count, bounded reads, hashes, dashboard SRI, and generation are checked before browser acceptance.
- A private `HERMES_HOME` exercises the official Hermes `0.20.0` commit `f5be9236e00ddf2f2a412697f267078fc4ee068e`, real `hermes plugins enable --no-allow-tool-override skynet-edr`, authenticated same-origin proxy routes, and a real headless Chromium browser. This is a dashboard compatibility gate, not an autonomous-enrollment claim; the separate Hermes `0.19.0` enrollment cell remains fail-closed until its own exact gate passes.
- The same built DEB is used in two hosted lanes: normal package/systemd behavior and the producer-owned `status_alert_delivery_degraded` fixture. Publication reuses those gated bytes.
- Risk Explorer displays the version reported by the real Skynet-EDR API and preserves `Engine Online`, `Backend available`, passive mode, and valid telemetry-degraded behavior for producer-owned `alert_delivery` failures.

## Security posture

The dashboard remains same-origin and authenticated; browser code never accesses the daemon's port directly. The release remains detection-only and read-only. Filesystem validation rejects extra objects, symlinks, hardlinks, special files, writable payload objects, oversized files, hash/SRI drift, and ordinary replacement races by pinning and rechecking file descriptors. A hostile concurrent UID 0 can replace trusted ancestors or interfere with the verifier and remains outside this local deployment gate's threat boundary.

## Deployment and rollback

No live host deployment, service restart, tag, or publication is performed by this change. Deployment still requires separate approval for the exact DEB digest, host, and rollback artifact. Roll back by reinstalling the previously approved DEB, restoring its matching Hermes payload, and rerunning both exact identity planes through the packaged verifier.

## Residual limitations

Skynet-EDR remains a prerelease with no production support commitment. Incident notices are local stdout-only and best effort; counters reset with the daemon. Signing, provenance, SBOM policy, broader platform coverage, and hostile-root resistance remain future work.
