# Fail-closed Hermes enrollment (S3)

## Status

The repository ships a bounded enrollment transaction, deterministic fixture contract, and a package-owned privileged adapter at `/usr/libexec/skynet-edr/hermes-enrollment-adapter.py`. Release promotion and any autonomous `ENROLLED` support claim require the exact release SHA to pass the mandatory disposable Ubuntu 24.04/Hermes 0.19.0 clean-host gate documented below; deterministic fixtures alone are insufficient.

The only compatibility cell exercised by the transaction tests is Ubuntu 24.04, `x86_64`/`amd64`, systemd, Hermes `0.19.0`, Skynet-EDR plugin `0.5.0`. Every other distro, architecture, init system, Hermes version, dashboard-only runtime, and global-role setup is unsupported or unproven and fails closed.

## Command

`skynet-edr-hermes-enroll check|apply|verify|unenroll` consumes:

- `--request`: private JSON naming the OS account and numeric UID, the exact canonical `<pwd home>/.hermes` `hermes_home`, fixed `default` profile, exact host tuple, exact Hermes/plugin versions, reviewed unit names, restart authorization, and socket DAC+UID decisions. Custom profiles/homes and arbitrary missing or caller-selected privileged destinations are rejected as unsupported before creation;
- `--source`: exact trusted package payload directory. Non-fixture requests are
  pinned to `/usr/share/skynet-edr/hermes-plugin/skynet-edr`; `fixture: true` is
  test-only and must never be accepted by a future live adapter;
- `--state-root`: production is pinned to root-owned mode-`0700` `/var/lib/skynet-edr-hermes-enrollment`, outside daemon-writable `/var/lib/skynet-edr`; caller-selected roots are rejected by the shipped entry point;
- `--observations`: production accepts only the pinned base path, then derives metadata and observations under `targets/<sha256(uid,profile)>` inside that private root. The transaction, not the target process, atomically writes each isolated bounded adapter result as `0600`;
- `--adapter`: mutations are pinned to the root-owned, non-writable package adapter path. Arbitrary adapters are accepted only by the in-process deterministic test harness.

The production payload identity comes from the root-owned package manifest at
`/usr/share/skynet-edr/hermes-plugin/manifest.json`; caller-supplied manifest
fields are ignored outside deterministic tests. The compatibility name
`skynet-edr-install-hermes-plugin` delegates to this command. The former advisory
copy-and-print path is intentionally gone.

Output is one bounded JSON object with fixed `schema`, `state`, `category`, and `noop` fields. Raw request values, paths, environment, event data, credentials, and child stdout/stderr are never echoed. Only `ENROLLED` exits zero for `check`, `apply`, and `verify`. A successful `unenroll` exits zero only as `QUARANTINED`; exact repeats return the same state with `noop=true`. `MANUAL_RECOVERY_REQUIRED` fails closed and exits nonzero.

## Transaction and trust boundary

`check` is read-only. It resolves account/UID, rejects implicit root, relative/traversal/control-character paths, symlink/non-directory components, writable untrusted ancestors, unsupported host/version tuples, ambiguous authorization, malformed units, non-allowlisted payload entries, special/symlink/hard-linked files, and byte/size/mode/owner/version drift.

The privileged enrollment process and its private root-owned mode-`0700` state/quarantine tree are the S3 trust boundary. The target home, profile, and numeric UID remain hostile or cooperative only as described above. S3 validates root ownership, mode, and device and rejects target-UID-controlled or otherwise unsafe parents before mutation, but it does not provide descriptor-bound resistance to a second hostile UID 0 actor replacing an already-validated private parent path. Malicious or unsynchronized concurrent root mutation or replacement of that private tree is out of scope because root compromise already controls the local EDR. Operators and root automation must serialize through the managed lock and must not rename, replace, or mutate the private tree during `apply`, `verify`, `unenroll`, or manual recovery. Descriptor-relative `mkdirat`/`openat` plus `O_NOFOLLOW` hardening against concurrent root replacement is deferred to S4 (`t_9e46dd64`).

`apply` serializes on a private lock, pins the canonical home plus `plugins` and `desktop-plugins` with descriptor-relative `O_NOFOLLOW` opens, and rejects pre-existing links, special files, hard-linked files, writable directory components, and identity drift. It stages allowlisted generations below the private root-owned transaction directory, fsyncs them, then atomically renames them through pinned directory descriptors before any Hermes enablement read-back. S3 requires the private state root and target home to be on the same filesystem; split-filesystem layouts fail closed before mutation. It preserves prior bytes plus metadata and invokes only the reviewed adapter actions. `HERMES_HOME`, `HERMES_PROFILE`, and the expected generation are passed on every adapter action. Target Hermes actions execute after an explicit UID/GID/supplementary-group credential drop; installed files are owned by that numeric UID. The target Hermes account is a cooperative identity, not an integrity boundary against same-UID concurrent tampering or denial of service; descriptor/no-follow operations prevent such tampering from becoming a privileged path escape, and post-publication drift fails verification or rollback. Each action has a random transaction nonce. The parent creates a separate fresh attestation token, derives the one expected canary event ID from it, and accepts only an exact bounded adapter JSON result before atomically replacing the private observation. The successful attestation transaction nonce is bound into enrollment metadata and expires after 30 seconds, so stale/replayed observations fail closed. Once managed mutation has begun, any apply failure preserves the current target, prior generation, Desktop state, metadata, observations, staging/evidence, and diagnostics without adapter rollback, overwrite restoration, recursive cleanup, or pathname deletion. It durably records `MANUAL_RECOVERY_REQUIRED`; retries are fenced by that journal and do not mutate. Any safe handling is then the documented manual root recovery procedure below. Pre-mutation transaction-owned temporary staging may be removed only while no managed mutation has begun.

`verify` rereads installed bytes and observations. It requires an exact observation schema with no missing, unknown, or mistyped fields, enabled read-back, exact loaded generation, a fresh process boundary, healthy listener and transport, zero backlog/degradation, fresh numeric UID plus `gateway` role, and the exact correlated committed harmless canary receipt that opened no incident. An unrelated aggregate counter increase or synthetic flag never satisfies the proof. An otherwise valid observation older than 30 seconds is `VERIFY_REQUIRED/observation_expired`.

An exact delayed repeat of `apply` returns nonzero `VERIFY_REQUIRED/observation_expired` with `noop=true` while holding the pre-existing validated enrollment lock. It performs no repair, installation, adapter call, restart, or metadata/observation write. A future explicit authorized operation must re-attest; v0.5 provides no live read-only recovery path. Missing or hostile existing locks fail closed without creation or repair.

`unenroll` disables with fresh nonce-bound read-back, restores adapter-owned host state, then atomically detaches only the exact matching backend/Desktop generation, enrollment metadata, and observation through pinned parent descriptors. Linux `renameat2(RENAME_NOREPLACE)` moves each exact object to a same-filesystem, root-owned mode-`0700` transaction quarantine. Source/destination collisions, symlinks, hard links, special files, mounts, device disagreement, ownership drift, target-UID-controlled or otherwise unsafe parents, and malformed journals fail closed without overwrite or deletion. This does not extend the S3 guarantee to unsynchronized concurrent root replacement of an already-validated private parent path.

Non-destructive quarantine is intentional. Quarantined managed content, rollback authority, and the durable exact-schema transaction journal are never recursively purged or automatically removed on success, failure, crash recovery, or repeat commands. Disk space remains occupied until a root operator manually inspects and handles it. Automatic recursive purge and full crash-idempotent deletion are deferred to S4.

## Manual inspection and recovery

When the result is `QUARANTINED` or `MANUAL_RECOVERY_REQUIRED`, preserve `/var/lib/skynet-edr-hermes-enrollment/targets/<target-id>/transaction.json`, its recorded `quarantine/<transaction-nonce>/`, and adapter snapshots. As root, first inspect without following links:

```text
sudo stat -- /var/lib/skynet-edr-hermes-enrollment/targets/<target-id>/transaction.json
sudo find -P /var/lib/skynet-edr-hermes-enrollment/targets/<target-id>/quarantine/<transaction-nonce> -xdev -printf '%y %D:%i %u:%g %m %p\n'
sudo python3 -m json.tool /var/lib/skynet-edr-hermes-enrollment/targets/<target-id>/transaction.json
```

Compare every device/inode, owner, mode, name, and digest to the journal. Recovery is permitted only when the recorded quarantine object still has the exact identity, the recorded source parent is unchanged and on the same filesystem, and the destination name is absent. Use an audited `renameat2(RENAME_NOREPLACE)` tool through pinned directory descriptors; plain `mv`, copy, overwrite, path-following deletion, and recursive cleanup are not approved recovery commands. If any identity is ambiguous, leave the quarantine and journal untouched and escalate. After inspection or recovery, any eventual removal is a manual root responsibility; this release provides no automatic cleanup command.

## Adapter contract

The adapter is a security boundary, not arbitrary plugin output. It receives one action argument: privileged `prepare`, `rollback`, or `attest`, or target-identity `enable` or `disable`. It receives a minimal environment containing exact `HOME`, `HERMES_HOME`, `HERMES_PROFILE`, generation, target UID, action, and random transaction nonce. `attest` additionally requires the parent's absolute monotonic deadline, fresh token, and derived expected canary event ID. Target actions run as the requested non-root identity; host preparation, rollback, and attestation remain privileged and bounded. Every action has its own exact response schema; unknown fields, stale generic health fields, and Python boolean/integer aliases are rejected. Rollback returns an explicit `reload_required=true` and `RESTORED_VERIFIED` phase while preserving rollback authority for manual inspection. Stdout/stderr are never forwarded, and the parent writes trusted metadata plus the result privately.

`prepare` accepts no path overrides. The Hermes launcher entry remains fixed at `/usr/bin/hermes`: there is no `PATH` discovery, environment override, glob, or caller-selected command. The adapter accepts either the strict root-owned executable regular file at that entry or at most eight root-owned, single-link symbolic-link hops. Every hop is lexically normalized to an absolute path, has a complete root-owned non-writable non-symlink directory chain, and may not repeat; relative parent escapes, cycles, missing components, and excess depth fail closed. The resolved target must be a root-owned, single-link, non-group/world-writable executable regular file, and that resolved target—not the entry symlink—is used for plugin enable/disable/list, rollback read-back and restore, and final attestation read-back. Concurrent hostile UID 0 replacement after validation remains within the S3 root-race limitation above; an unprivileged account cannot replace any accepted hop. `SYSTEMCTL`, `USERMOD`, and `GPASSWD` retain their direct strict regular-file checks.

The adapter edits only `/etc/skynet-edr/config.toml`, the exact `skynet-edr-ingest` group, and `/etc/systemd/user/hermes-gateway.service.d/50-skynet-edr.conf`. The TOML parser rejects duplicate/missing/mistyped owned keys, nonstandard socket/group values, root authorization, and roles other than `gateway`; the serializer changes only `enabled`, `socket_group`, `allowed_uids`, `allow_root`, and `required_reported_roles`. The exact reviewed global user-unit drop-in remains the persistent preferred path: it binds the gateway role and exact lowercase 64-hex package generation as `SKYNET_EDR_PLUGIN_GENERATION`, uses systemd `%h/.hermes` for per-user home isolation, fixes `HERMES_PROFILE=default`, and sets `PYTHONDONTWRITEBYTECODE=1`. Hermes 0.19 may install a higher-precedence per-user unit fragment that prevents systemd from loading that global drop-in. Therefore, after the authorized complete user-manager restart, the adapter imports the same six managed values into the new manager for the current attested epoch, passing only their names in `systemctl import-environment` arguments, then explicitly restarts the reviewed gateway and daemon under the original absolute deadline. During the authorized attestation epoch the environment also binds only the fresh parent-generated token; before recording success, the adapter removes that token from the manager with exact bounded read-back while preserving the already-attested gateway process identity, and transactionally restores the token-free managed drop-in. Every failure path exits and disarms the attestation watchdog before starting a distinct bounded cleanup deadline, then attempts both token-free drop-in restoration and complete managed manager-environment cleanup; through a parent-created private inherited pipe, the adapter emits one fixed cleanup marker at watchdog expiry or immediately before other post-context cleanup. Only that marker permits the enrollment parent to keep the adapter alive until the single matching bounded cleanup deadline; an unmarked hung adapter is killed at the unchanged protocol deadline, every late success is rejected, and incomplete cleanup fails as `rollback`. A later manager restart, reboot, or hostile manager-environment mutation is not silently repaired: exact read-back fails closed as `DRIFTED` until an authorized reapply establishes and attests a new epoch. Rollback/unenroll unsets exactly those managed manager variables, restarts the reviewed gateway and daemon, and rejects any managed-name residue in bounded manager-environment read-back. The plugin independently creates a fresh 256-bit lowercase-hex runtime nonce in each process; the adapter never generates, injects, or reuses that nonce. Every required configured value, including the token during attestation, is read back from the running gateway. Runtime `__pycache__` content remains forbidden managed-tree drift and is never allowlisted. Custom homes/profiles are unsupported. The adapter snapshots exact prior config/drop-in bytes, ownership, modes, and prior group membership in private root-owned state before mutation. Failed initial read-back removes newly-created baseline/scope/adapter-state residue; `rollback` restores a completed snapshot and removes only membership it added. Child output is capped at 64 KiB, duplicate-key JSON is rejected, and raw Hermes/systemctl/API diagnostics are discarded.

The only reviewed producer unit is `hermes-gateway.service`; dashboard, template, caller-selected, and multiple-unit requests fail closed. `restart_authorized=true` authorizes a root restart of the complete `user@UID.service`, followed by the reviewed `skynet-edr.service`, so the user manager and gateway inherit the newly granted ingest group. This interrupts and restarts every user service managed for that account, not only Hermes; operators must treat that account-wide availability impact as the authorization blast radius. Without that authorization the transaction remains `RELOAD_REQUIRED` and does not restart the user manager.

The parent creates one absolute 15-second monotonic deadline immediately before invoking the privileged attestation lane. That same deadline bounds adapter execution, every systemd/Hermes child, process and group read, loopback status connect/read, poll, sleep, parent observation persistence, enrollment metadata persistence, and final assessment; no operation starts at or after expiry and no result completing at or after expiry is accepted. After capturing all prior identities, the lane stops the old daemon before the required manager restart, environment import, gateway restart and daemon restart sequence. This forces the token-free gateway startup canary into the plugin's existing durable fallback until the fresh daemon listener is ready, preventing an acknowledgement by the old daemon from disappearing with its in-memory source counters. It captures pre-restart and changed post-restart `(MainPID, /proc start ticks, systemd monotonic exec start)` identities for `user@UID.service`, `hermes-gateway.service`, and `skynet-edr.service`, proves prior identities are gone, and revalidates all three unchanged after final plugin/source read-back. Missing, unchanged, replaced, late, or disagreeing identity evidence fails closed and preserves rollback evidence.

After exact environment/group read-back, including exact `skynet-edr-ingest` socket ownership and membership for both gateway processes, attestation waits for exactly one fresh protocol-v3 gateway source bound to the target UID, configured generation, an independent plugin-generated runtime nonce, and the kernel-observed PID/start identity of the verified gateway. The runtime nonce must differ from the generation and attestation token. The status root and selected source must have the exact reviewed field sets and primitive types; Python boolean/integer aliases, missing fields, and unknown fields fail closed. A known prior v3 epoch is selected only by that same exact typed source tuple and must rotate its runtime nonce; unrelated generations may remain, but another protocol-v3 source for the target UID and generation is rejected. Zero sources continue only within the same deadline; duplicate, stale/replayed, legacy/event-only, unhealthy, generation/nonce-confused, or PID/start-mismatched sources fail closed. After starting its protocol-v3 worker, the enabled gateway plugin derives the existing `evt_skynet_attest_<sha256>` contract from the exact lowercase 64-hex token and queues exactly one canonical, token-free `agent.telemetry.attestation` informational startup canary per runtime process. Registration is the sole fixed-ID producer path, is one-shot under lock, and never retries; missing or malformed tokens fail dark. Former `SKYNET_EDR_ATTEST_V1`/`SKYNET_EDR_ATTEST_ACK_V1` prompt text is ordinary token-free LLM telemetry and cannot emit an enrollment event ID. The adapter never invokes `hermes chat`, an LLM, a provider, or a tool, so attestation has no inference dependency. The baseline `commit_sequence` and `events_persisted_total` are recorded only from the exact gateway source. If the producer queued the canary before daemon listener readiness, the same deadline may observe its first clean replay as the source's sole persisted event; otherwise it observes the baseline then the advancement. Success requires an isolated exact `+1` Persisted-only advancement of both counters on the same source tuple, plus that exact event ID, receipt status `persisted`, and `incidents_opened=0`, while malformed, dropped, duplicate, collision, and error counters remain typed zero. There is no compatibility hook or second timing lane. Those corrected external contracts still require independent exact-SHA review and a fresh disposable clean-host rerun before promotion.

The fixture tests mock service/config boundaries and are not permission to mutate a live system.

## Mandatory clean-host promotion gate

Before any support claim changes from unproven to supported, a separate reviewed task must ship and exercise the live adapter in a disposable booted Ubuntu 24.04 amd64/systemd host with Hermes 0.19.0. The gate must prove package manifest ownership, temporary target user/profile with canonical `<pwd home>/.hermes`, exact daemon TOML edits, socket group plus `SO_PEERCRED` UID allowlist, exact unit/drop-in environment, expected no-restart `RELOAD_REQUIRED`, approved restart and rollback, post-restart exact v3 producer health, exact correlated canary receipt, fake-secret byte scans, cooperative concurrent applies serialized through the managed lock without external root mutation of the private tree, fault injection at copy/fsync/rename/enable/config/drop-in/attest stages, package partial-upgrade/removal, and repeatable unenroll while preserving fallback/checkpoint/log/database evidence. Hostile concurrent root replacement remains outside the S3 clean-host claim and is deferred to S4. No live operator host or profile may be used.

Until that gate passes, the literal operational verdict is `S3_ADAPTER_BLOCK`.
